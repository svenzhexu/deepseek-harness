实战：开发自己的程序

这一章不再讲新概念，而是把前面所有东西拼起来：一个能真正使用的待办清单 CLI。 它有服务、事件、依赖、配置、错误处理、测试，也可以加上 HMR。跟着做完，你会得到一套可以继续扩展的项目骨架。

难度 动手 用时 约 60 分钟 前置 第 4–9 章 产物 可运行的 todo CLI
完成后你会得到
  • 一个支持 add / list / done 的命令行程序；
  • 一个带 schema 校验、可被替换的存储服务；
  • 一个通过事件解耦的统计插件；
  • 一份可读的 cordis.yml，以及一组能跑的测试；
  • 知道下一步如何把它扩展成多列表、Web API 或 SQLite 版本。

第 1 步：写存储服务

先写 store.ts。它负责四件事：加载 JSON、保存 JSON、提供增删改查、在变化时发出事件。 注意它不关心命令行，也不知道谁在监听。

store.tsts
import { readFile, writeFile } from 'node:fs/promises'
import { Service, type Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export interface Todo {
  id: number
  title: string
  done: boolean
}

export interface Config {
  file: string
}

export const name = 'todo-store'

export const Config: Schema<Config> = Schema.object({
  file: Schema.string().default('./todos.json'),
})

declare module '@deepseek-ai/cordis' {
  interface Context {
    todoStore: TodoStore
  }
  interface Events {
    'todo/added'(todo: Todo): void
    'todo/completed'(todo: Todo): void
  }
}

export class TodoStore extends Service {
  private todos: Todo[] = []
  private nextId = 0

  constructor(ctx: Context, public config: Config) {
    super(ctx, 'todoStore')
  }

  async [Service.init]() {
    try {
      const content = await readFile(this.config.file, 'utf8')
      this.todos = JSON.parse(content) as Todo[]
    } catch (error) {
      if ((error as NodeJS.ErrnoException).code !== 'ENOENT') throw error
    }
    this.nextId = this.todos.reduce((max, todo) => Math.max(max, todo.id), 0)
    console.log(`[store] loaded ${this.todos.length} todos`)
  }

  async add(title: string) {
    const todo: Todo = { id: ++this.nextId, title, done: false }
    this.todos.push(todo)
    await this.save()
    this.ctx.emit('todo/added', todo)
    return todo
  }

  async complete(id: number) {
    const todo = this.todos.find((todo) => todo.id === id)
    if (!todo) throw new Error(`todo #${id} not found`)
    if (!todo.done) {
      todo.done = true
      await this.save()
      this.ctx.emit('todo/completed', todo)
    }
    return todo
  }

  list() {
    return [...this.todos]
  }

  private async save() {
    await writeFile(this.config.file, JSON.stringify(this.todos, null, 2))
  }
}

export function apply(ctx: Context, config: Config) {
  ctx.plugin(TodoStore, config)
}

这段代码里有几个值得停下来看的点：

  • export const Config：告诉 Loader“我的配置长这样”。file 有默认值，所以即使 yml 里不写，也能启动。
  • declare module：把 todoStore 加进 Context， 把两个事件加进 Events。它只影响类型，不生成运行时代码。
  • [Service.init]：构造函数只做注册，异步加载放到 init。加载失败会让插件 FAILED， 不会留下半初始化状态。
  • this.ctx.emit：服务只负责“宣布发生了什么”，不负责“谁来处理”。
  • export function apply：Loader 加载的是这个函数插件；它再把 TodoStore 作为子插件挂载。服务注册归子 Fiber 管。

第 2 步：写一个只监听事件的插件

stats.ts 不认识 TodoStore，也不需要 inject。它只是订阅两个事件， 在事件发生时打印一行。这就是“发布 / 订阅”的好处：新增统计功能不需要改存储代码。

stats.tsts
import type { Context } from '@deepseek-ai/cordis'
import type { Todo } from './store.ts'

export const name = 'todo-stats'

let added = 0

export function apply(ctx: Context) {
  ctx.on('todo/added', (todo: Todo) => {
    added += 1
    console.log(`[stats] +1 (${added}) ${todo.title}`)
  })

  ctx.on('todo/completed', (todo: Todo) => {
    console.log(`[stats] done #${todo.id} ${todo.title}`)
  })
}
模块级状态与热更新

这里的 added 是模块级变量。普通运行没问题，但 HMR 重新导入模块时它会归零。 真实项目里如果需要跨重载保留状态，应该把计数放进一个服务，或用持久化存储。 这个例子故意保留模块变量，是为了让你看到这个边界。

第 3 步：写命令行入口

cli.ts 是唯一接触 process.argv 的插件。它声明依赖 todoStore， 因此 Cordis 会等存储初始化完成后再执行它。

cli.tsts
import type { Context } from '@deepseek-ai/cordis'
import type { Todo } from './store.ts'

export const name = 'todo-cli'
export const inject = ['todoStore']

function print(todos: Todo[]) {
  if (!todos.length) {
    console.log('（还没有待办）')
    return
  }
  for (const todo of todos) {
    console.log(`${todo.done ? '✓' : '○'} #${todo.id} ${todo.title}`)
  }
}

export async function apply(ctx: Context) {
  const [command = 'list', ...args] = process.argv.slice(2)

  try {
    switch (command) {
      case 'add': {
        const title = args.join(' ').trim()
        if (!title) {
          console.log('用法: add <标题>')
          return
        }
        const todo = await ctx.todoStore.add(title)
        console.log(`已添加 #${todo.id}: ${todo.title}`)
        break
      }
      case 'done': {
        const id = Number(args[0])
        if (!Number.isInteger(id)) {
          console.log('用法: done <id>')
          return
        }
        const todo = await ctx.todoStore.complete(id)
        console.log(`已完成 #${todo.id}: ${todo.title}`)
        break
      }
      case 'list': {
        print(ctx.todoStore.list())
        break
      }
      default:
        console.log('命令: add <标题> | list | done <id>')
    }
  } catch (error) {
    console.error(`[cli] ${(error as Error).message}`)
    process.exitCode = 1
  }
}

inject: ['todoStore'] 是这一章的关键。它让 CLI 不必关心“存储有没有准备好”， 也让“换一个存储实现”不需要改 CLI 的任何一行。

第 6 步：写测试

Cordis 的一个隐性好处是可测试性：你可以在测试里创建一个独立的根上下文，挂载真实服务， 用临时文件作为数据源，不需要启动 CLI 或整个应用。

tests/store.test.tsts
import assert from 'node:assert/strict'
import { mkdtemp, rm } from 'node:fs/promises'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import test from 'node:test'
import { Context } from '@deepseek-ai/cordis'
import { TodoStore } from '../store.ts'

test('add, complete and persist', async () => {
  const dir = await mkdtemp(join(tmpdir(), 'cordis-todo-'))
  const file = join(dir, 'todos.json')
  const ctx = new Context()

  try {
    await ctx.plugin(TodoStore, { file })

    const todo = await ctx.todoStore.add('write tests')
    assert.equal(todo.id, 1)
    assert.equal(ctx.todoStore.list().length, 1)

    const done = await ctx.todoStore.complete(1)
    assert.equal(done.done, true)

    const reloaded = new Context()
    try {
      await reloaded.plugin(TodoStore, { file })
      assert.equal(reloaded.todoStore.list()[0]?.done, true)
    } finally {
      await reloaded.fiber.dispose()
    }
  } finally {
    await ctx.fiber.dispose()
    await rm(dir, { recursive: true, force: true })
  }
})

test('complete rejects unknown id', async () => {
  const dir = await mkdtemp(join(tmpdir(), 'cordis-todo-'))
  const ctx = new Context()

  try {
    await ctx.plugin(TodoStore, { file: join(dir, 'todos.json') })
    await assert.rejects(() => ctx.todoStore.complete(99), /not found/)
  } finally {
    await ctx.fiber.dispose()
    await rm(dir, { recursive: true, force: true })
  }
})
终端sh
node --import tsx --test tests/store.test.ts

测试里没有 mock，也没有启动 Loader。你测的就是真实的服务与真实的文件读写，只是把路径换成了临时目录。 这就是“在子上下文里换提供者”的另一种用法：换的是配置，而不是实现。

第 7 步：故意制造一次配置错误

把 cordis.yml 里的 file 改成数字：

cordis.yml（错误示例）yaml
- id: store
  name: './store.ts'
  config:
    file: 123

再次运行，插件会在启动阶段失败，而不是等到写文件时才炸。你会看到 ValidationError， 错误信息指出 file 字段期望字符串。修回 './todos.json' 即可。

这就是 schema 的价值

没有 schema 时，123 会一路传到 readFile，报一个与“配置写错”毫无关系的错误； 有 schema 时，错误在入口处就被拦住，并且告诉你哪个字段、期望什么类型。

第 8 步：打包与发布

开发阶段用 tsx 直接跑最方便。要发布给别人用，建议编译成 JavaScript，并用一个自己的 main.js 替代仓库里的启动器：

main.ts（相当于 bin.js 的自写版本）ts
import { Context } from '@deepseek-ai/cordis'
import Loader from '@deepseek-ai/cordis-plugin-loader'
import { pathToFileURL } from 'node:url'

const ctx = new Context()
ctx.baseUrl = pathToFileURL(import.meta.dirname).href + '/'

await ctx.plugin(Loader)
await ctx.loader.create({
  name: '@deepseek-ai/cordis-plugin-include',
  config: { path: './cordis.yml' },
})
await ctx.loader.await()

它和 vendor/cordis/bin.js 做的是同一件事：创建根上下文、设置基准路径、挂 Loader、 让 Include 读取配置。区别只是 baseUrl 指向项目目录而不是当前工作目录，这样用户从任何地方执行都能找到配置。

package.jsonjson
{
  "name": "cordis-todo",
  "private": true,
  "type": "module",
  "bin": {
    "todo": "./dist/main.js"
  },
  "scripts": {
    "build": "tsc -p tsconfig.json",
    "test": "node --import tsx --test tests/store.test.ts"
  },
  "dependencies": {
    "@deepseek-ai/cordis": "^4.0.0",
    "@deepseek-ai/cordis-plugin-include": "^1.0.0",
    "@deepseek-ai/cordis-plugin-loader": "^1.0.0",
    "@deepseek-ai/schemastery": "^3.0.0"
  }
}

发布时还要把 cordis.yml、编译后的 store.js 等文件一起打包； 如果配置里用相对路径，确保它们相对的是打包后的目录。一个更省事的做法是用 tsdown / esbuild 打成一个入口文件，把插件模块也包含进去。

tsconfig.json（最小示例）json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "outDir": "dist",
    "rootDir": ".",
    "strict": true,
    "skipLibCheck": true

}
版本号只是示例

上面的依赖版本是示意，实际请以你安装到的版本为准。Cordis 4.x 的 API 仍可能变化； 如果是团队项目，建议锁定版本并在升级时跑一遍测试。

第 9 步：接下来可以加什么

删除与编辑 给 store 加 remove / rename，再发一个 todo/removed 事件。CLI 只加一个分支。
多列表 / 多租户 用 isolate: { todoStore: true } 建两个组，各自一个数据文件；CLI 通过参数选择上下文。
换成 SQLite 写一个 SqliteStore extends Service，实现同样的方法；消费者一行不改。
加 Web API 新增一个插件，inject todoStore，把 add / list 暴露成 HTTP 接口。
加 HMR 按第 9 章配置 HMR，改 CLI 提示语后不用重启；同时检验 Effect 是否写对。
加撤销 / 重做 把每次变更记录成命令对象，store 负责执行与回滚；这是一个更接近真实产品的练习。

这个项目用到了什么

概念在项目里的位置作用
Contextapply(ctx) 的参数插件访问服务与事件的入口。
ServiceTodoStore把存储能力注册为 todoStore。
injectcli.ts保证 CLI 在存储就绪后才执行。
Eventtodo/added、todo/completed让统计插件与存储解耦。
EffectService.init 与自动注册异步初始化；服务、监听器随 Fiber 卸载。
Configstore.ts 的 schema校验 file，提供默认值。
Loadercordis.yml声明式装配，不用改代码。
声明合并declare module让 ctx.todoStore 与事件名有类型。

本章小结

  • 一个完整的 Cordis 程序由“配置 + 若干插件 + 一个启动器”组成。
  • 服务负责能力，事件负责通知，inject 负责顺序，Effect 负责清理。
  • schema 让配置错误在启动时暴露；默认值让调用方只写关心的字段。
  • 测试可以只创建根上下文、挂载真实服务，用临时目录隔离副作用。
  • 替换实现时消费者不用改，这是服务寻址最重要的回报。
  • 发布时要处理路径、编译与配置文件打包；开发阶段用 tsx 即可。

自测一下

为什么 cli.ts 需要 inject: ['todoStore']，而 stats.ts 不需要？

CLI 直接调用 ctx.todoStore.add()，必须在存储初始化完成后才能执行，所以声明硬依赖。 统计插件只监听事件，不调用服务；即使它先加载，事件发生时它已经在监听了。它不需要等待 store。

如果要把 JSON 存储换成 SQLite，需要改哪些文件？

只需要新增一个实现同样方法（add / complete / list）的服务， 并在 cordis.yml 里换掉提供者。CLI、统计、事件定义都不需要改。

store.ts 里的 ctx.plugin(TodoStore, config) 产生的是谁的子插件？卸载时会怎样？

它产生的是 apply 这个入口插件的子 Fiber。入口插件卸载时，会连同子 Fiber 一起卸载， 并等待它的清理完成；TodoStore 的服务注册随之撤销，依赖它的 CLI 也会被卸载。
