一句话说清 Cordis

Cordis 是一个用 TypeScript 写的插件框架。它不负责你的业务，而是负责让许多块业务能够 安全地拼在一起、随时换掉、热更新，再干净地拆开。

Cordis 以 Context 为容器，以插件为单元，用 Fiber 管理生命周期， 用 Service 和 Event 连接协作。

容器 所有能力都有一个名字，挂在 ctx 上。插件按名字取用，不直接 import 实现。
生命周期 每次挂载产生一个 Fiber；卸载时，这个插件注册过的一切都会自动撤销。
协作 服务用于“直接调用”，事件用于“广播通知”；两者都不要求双方互相认识。

如果你现在只觉得“好像很抽象”，没关系。第 1 章会从一段没有 Cordis 的代码开始，让你亲眼看到这些词分别在解决什么问题。

Learning outcomes
  • 用自己的话解释 Cordis 是什么，以及它不是什么；
  • 说清 Context、Plugin、Fiber、Service、Event、Effect 各自的职责；
  • 看懂一个 Cordis 项目的启动过程，知道插件为什么“没有输出”；
  • 写出带依赖声明、配置校验和资源清理的插件；
  • 用 cordis.yml 组装应用，并理解 Loader 与 HMR 在做什么；
  • 判断什么时候该用 Cordis，什么时候一个 main 函数就够了；
  • 独立完成一个可运行的命令行程序，并知道下一步怎么扩展它。

阅读约定

为了让你少迷路，全书使用固定的视觉语言：

  • 代码块右上角有“复制”按钮；标题栏写着文件名时，表示这是一个完整文件，而不是片段。
  • 蓝色提示框补充概念，绿色是实践建议，橙色是需要注意的坑，红色是常见错误，紫色是生活类比，灰色是可以暂时跳过的进阶内容。
  • 每章末尾有 2–3 道自测题，点开才显示答案。先自己想，再点开。
  • 带 $ 的命令在项目根目录执行；示例输出中的省略号表示“其余输出省略”。
  • 术语第一次出现时会给出英文，附录有完整对照表。不要背 API，先理解因果。
包名说明

本指南的代码使用本仓库中的包名：@deepseek-ai/cordis、@deepseek-ai/cordis-plugin-loader。 它们和上游的 cordis、@cordisjs/plugin-loader 是同一套 API，只是 DeepSeek Harness 把 Cordis vendor（复制进仓库）后改了作用域；@deepseek-ai/schemastery 同理对应上游的 schemastery。 你在网上看到的 Cordis 文章若使用上游包名，把名字替换即可，概念完全一致。

开始之前

你不需要会 TypeScript，但最好写过一点点 JavaScript：知道 function、对象、import 和 async/await 就够了。遇到陌生语法时，正文会停下来解释；第 1 章也有一张 TypeScript 速览。

想跟着敲代码，需要 Node.js 22 以上，以及本仓库已经执行过 pnpm install。如果只是想读懂，直接翻页即可， 所有示例都给出了预期输出。

版本说明

本指南基于本仓库 vendor 的 Cordis 4.0（上游 4.0.0-rc.7，包清单版本 4.0.5）。 Cordis 仍处于快速演进阶段，个别 API 可能随版本变化；当文字与源码冲突时，以 vendor/cordis/src 为准。
