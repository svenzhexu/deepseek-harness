## 一、核心概念

### 10.1 四层组合

```
profile              一个具名组合，存在 Harness home
  └── bundle         可分发的插件行集合（package.json 的 dsh.bundle 指向一个 patch 文件）
        └── patch    按 row id 覆盖或插入
              └── preset   只在某个 agent 内部生效的子组合
```

### 10.2 profile：组合的身份

一个 profile 记录三件事：

1. 它叠了哪些 bundle（有序）。
2. 它装了哪些外部插件。
3. 用户自己的 `cordis.patch.yml`。

内置模板：`web` / `headless` / `sdk` / `sdk-minimal` / `acp`。

**硬规矩**：应用只能通过命名 profile 启动。不能"直接 new 一棵 Cordis 树"，也不能"给我个 bin 当应用跑"。这条规矩由 `verify-application-entrypoints` 强制。

为什么这么严：如果每个人都能自造启动路径，产品就没法保证"你跑的和我跑的是一样的东西"。

### 10.3 bundle：可分发的行集合

`../packages/bundle/base/package.json` 里那段：

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" }
}
```

- `dsh.bundle` 指向 patch 文件。
- `dsh.profile` 列出一个 profile 用哪些 bundle。

**bundle 的依赖必须写进 `dependencies`**。否则裸插件名解析不到——这条由 `verify-cordis-config` 检查。

### 10.4 patch：整行替换，不是深合并

```yaml
- insert:
    - id: my-tool
      name: '@acme/dsh-tool-ticket'
      config:
        endpoint: 'https://...'
```

或者覆盖已有行：

```yaml
- id: compaction-basic
  config:
    threshold: 0.8
```

**关键规则**：patch 替换目标的**整个 `config`**，不是往里 merge。

这条规则会坑你：你以为只改了 `threshold`，结果把同一个 config 里的 `keepRecentTurns` 也抹掉了（因为新 config 里没写）。

正确写法：**完整重写这个 config**，或者接受默认值。

### 10.5 层叠顺序

对一棵空的入口列表，依次应用：

```
1. profile 的有序 bundle
2. profile 的 cordis.patch.yml
3. Harness home 的 patch
4. --patch 传入的 overlay（按传入顺序）
```

**后层覆盖前层**，按 row id 定位。

`preset` 是另一个维度：它把同样的操作应用在某个声明内部的 `config.plugins` 上，优先级规则相同，但作用域只在这个 agent 内。

### 10.6 preset：一个进程里的不同 agent

`agent-preset` 让一个 session 选择一套子插件：

```yaml
- id: agent-preset-registry
  name: '@deepseek-ai/dsh-agent-preset-registry'
  config:
    default: standard

- id: preset-standard
  name: '@deepseek-ai/dsh-agent-preset'
  config:
    id: standard
    plugins: []
```

用途：同一个进程里，"客服 agent"和"研发 agent"可以有不同工具集、不同人格、不同权限，而不用起两个进程。

**注意**：定义是**急切加载**的，但编辑只影响**之后创建**的 agent。已经存在的 agent 不会热更新——这是刻意的，避免运行中能力突变。

### 10.7 `!!js` 的边界

`cordis.yml` 允许 `!!js` 表达式，但**只在两个位置**：

- 插件 `config` 内部
- 入口的 `disabled` 字段

其他元数据必须保持字面量。原因：配置是数据，不是程序；只在需要条件计算的地方开这个口子。

## 三、精读片段

`../apps/cli/config/examples/mcp-memory/mcp-reference-memory.cordis.yml` 全文只有 13 行，但它把 overlay 的写法展示得很完整：

```yaml
- insert:
    - id: memory-mcp-reference
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: reference_memory
        transport: stdio
        command: mcp-server-memory
        cwd: !!js process.cwd()
        env:
          MEMORY_FILE_PATH: !!js >-
            process.env.MEMORY_FILE_PATH?.trim() || ...
```

三个可学的点：

1. **`insert` 是数组**：一次可以插多行。
2. **`id` 自己起**：只要是这个树里唯一的地址就行。
3. **`!!js` 用在 config 里**：这里用它求 `process.cwd()` 和拼默认路径。注意它读环境变量时做了 `?.trim() ||` 兜底——配置代码也要防御。

## 四、动手

### 10.1 先看基线

```powershell
pnpm dsh --profile web --dump-config > tmp/tree-before.txt
```

### 10.2 写一个最小 overlay

```yaml
# tmp/my-agent.cordis.yml
- insert:
    - id: my-first-tool
      name: '@deepseek-ai/dsh-tool-todo'
      config: {}
```

（先用一个已存在的工具包练手，避免自己写代码。）

```powershell
pnpm dsh --profile web --patch ./tmp/my-agent.cordis.yml --dump-config > tmp/tree-after.txt
```

对比两份文件，确认你插入的行出现了、位置符合预期。

### 10.3 覆盖一个已有行

选一个 config 简单的插件（比如某个工具的开关），用它的 id 写一条覆盖，观察 `--dump-config` 里的 config 是**整体被替换**而不是合并。

**这个实验必须做**，因为它是第 11 天之后最容易踩的坑。

### 10.4 试一个 preset

在一个 overlay 里加一条 preset，配置一个空 `plugins: []`，然后用 `--dump-config` 看它出现在哪里。暂时不需要让它生效，理解结构即可。

## 六、常见误解

**"patch 会和我原来的 config 合并。"**
不会。这是本仓库最容易踩的坑之一。覆盖时要么写全，要么接受默认值。

**"我可以直接写个脚本 new 一个 Context 跑 agent。"**
可以用于测试和学习，但**产品路径必须走命名 profile**。这条规矩的动机是保证"用户跑的和开发者跑的是同一个东西"。

**"`cordis.yml` 里的行顺序决定加载顺序。"**
不决定。加载由服务可用性驱动（第 2 天讲过）。行顺序只影响可读性和 patch 定位。
