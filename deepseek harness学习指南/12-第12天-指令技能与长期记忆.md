# 第 12 天 · 指令、技能与长期记忆

> **本日目标**：把"我们公司的业务规矩"交给模型，并且分清三种知识载体各自的适用场景。

---

## 一、核心概念

### 12.1 三种载体，三种成本

| 载体 | 何时进上下文 | 成本 | 适合放什么 |
|---|---|---|---|
| **AGENTS.md 类指令** | 每一轮都在 | 高（常驻） | 术语表、硬性禁令、输出格式 |
| **skill** | 目录摘要常驻，正文按需 | 低 | 分场景的操作规程 |
| **工具** | schema 常驻 | 中 | 能执行的动作 |

选错的典型症状：

- 把长篇操作手册塞进 AGENTS.md → 每轮烧几千 token，还稀释注意力。
- 把必须遵守的禁令做成 skill → 模型不加载就不会知道，出事。
- 把可执行动作写成文档 → 模型只能"说"，不能"做"。

**判断口诀**：**每轮都必须知道的 → 指令；需要时才查的 → skill；需要动手的 → 工具。**

### 12.2 AGENTS.md 是怎么进上下文的

`../packages/context/agent-instructions` 负责扫描工作区里的指令文件，把它们注入成 prompt 段落。

关键性质：

- **自动发现**：从工作目录向上找，或按配置的根扫描。
- **作用域感知**：不同工作区可以有不同指令。
- **每轮可见**：它常驻，所以必须短。

你在仓库根看到的那个 `AGENTS.md`，就是通过这个包变成模型指令的——**它同时也约束着 AI 自己改这个仓库时的行为**。这是 DSH 一个很聪明的自举：给 agent 的规则和给贡献者的规则是同一份文件。

### 12.3 skill：目录常驻、正文按需

一个 skill 就是一个目录（或平铺文件）：

```
<skill-root>/
  ticket-triage/
    SKILL.md          ← 必需
    references/       ← 可选，正文里链接进去按需读
```

`SKILL.md` 的 frontmatter（见 `../packages/skill/skill-filesystem/README.md:36`）：

| 字段 | 必填 | 作用 |
|---|---|---|
| `name` | 是 | 唯一名 |
| `description` | 是 | **决定模型什么时候加载它** |
| `whenToUse` | 否 | 更细的触发说明 |
| `metadata` | 否 | 任意元数据 |
| `disable-model-invocation` | 否 | 不暴露给模型 |
| `user-invocable` | 否 | 不暴露给人类命令 |

**发现规则**（容易踩坑）：

- 只有 `<name>/SKILL.md` 或扫描根**顶层**的 `<name>.md` 会被发现。
- **嵌套的 `**/SKILL.md` 故意不发现**——避免你无意中把 `node_modules` 里的东西当技能。

**生命周期**：目录（frontmatter）和正文（body）是分开的。每次加载都重读文件，所以改正文不需要清缓存；目录会被 watch，新增/改名/删除不需要重启。

### 12.4 官方 skill 长什么样

`../packages/preset/agent-preset/skills/agent-experience/SKILL.md` 是一个极好的范例：

```markdown
---
name: agent-experience
description: Use when writing or changing a model-facing tool definition ... to make information discoverable and use context efficiently.
---

- **Start with minimal context:** expose purpose, available actions, and constraints first...
- **Make discovery explicit:** every deferred resource needs a clear description...
```

注意三点：

1. **`description` 写得像触发条件**，不是像标题。模型靠它决定加载不加载。
2. **正文是给模型读的操作要点**，不是给人读的散文。
3. **篇幅受控**：预设 README 里提到，每个 SKILL.md 渲染成工具结果后要控制在 8192 字符以内，超过会被工具结果裁剪器处理。

### 12.5 记忆：三种可选方案

第 9 天讲过 DSH **没有内置向量记忆**。今天落地，有三条路：

| 方案 | 投入 | 能力 | 适合 |
|---|---|---|---|
| MCP memory server | 最低 | 现成的增删查 | 快速验证 |
| 基于 `session-query` 的工具 | 中 | 检索历史会话 | 你已经有很多会话 |
| 自建 `remember` / `recall` 工具 | 最高 | 完全贴合业务 | 生产 |

前两种在 `../docs/user/guide/mcp-memory.md` 有可运行的 overlay。

第三种的核心设计问题不是"存哪"，而是**"什么时候记、记什么、什么时候忘"**：

- **记**：模型主动调 `remember`，还是每轮自动摘要？
- **记什么**：事实、偏好、还是结论？建议只记**会被复用的稳定事实**。
- **忘**：没有遗忘策略的记忆库，三个月后就是垃圾场。

### 12.6 一条容易被忽略的规则

记忆工具本身也是工具，所以：

- 它的 schema 也是常驻上下文成本。
- 它的结果也会落进会话日志。
- 它的失败也要结构化返回。

**不要把记忆做成"内核特权"。** 在 DSH 的模型里，它就是一个普通能力，挂在 `ctx.tools` 上。

## 三、精读片段

`../packages/preset/agent-preset/skills/agent-experience/SKILL.md` 的第 15 行：

> **Delete obvious constraints.** Omit rules the model learns from the call result, such as a missing file failing to read or a failed send not being delivered.

这句话点出了写 skill 最容易犯的错：**把模型能从结果里自己学到的东西，又写进指令里。**

比如你写"如果文件不存在，read 会失败"——这句话纯属浪费上下文，因为模型调用 `read` 得到失败结果时自然就知道了。

**判断标准**：这条规则能不能从一次工具调用的结果里推出来？能，就删掉。

## 四、动手

### 4.1 写一个业务 skill

建 `skills/ticket-triage/SKILL.md`：

```markdown
---
name: ticket-triage
description: Use when a customer ticket needs classification or an SLA decision. Covers priority rules and escalation thresholds.
---

1. 先调用 `lookup_ticket` 拿到工单详情。
2. 按客户等级定基数：企业版 P1，专业版 P2，免费版 P3。
3. 命中任一升级条件则上调一级：涉及资金损失、涉及数据泄露、客户已三次催促。
4. 输出格式固定为：`优先级 / 依据 / 建议动作 / 是否需要人工`。
```

把 `skills/` 目录挂到扫描根上，重启验证：

- 目录摘要里有没有它？
- 让它处理一条工单，观察它是否加载了这个 skill。

### 4.2 改 AGENTS.md 做对照

在同一个工作区根写一个 `AGENTS.md`，只放**每轮都必须知道**的东西：

```markdown
# 客服工作区

- 所有对客户的回复必须使用中文，语气正式。
- 禁止在回复中承诺赔付金额，必须转人工。
- 工单优先级规范见 skill `ticket-triage`。
```

对比两者对上下文的影响：`AGENTS.md` 每轮都在，skill 只在相关时加载。

### 4.3 接一个记忆

三选一，建议先做最快的：按 `../docs/user/guide/mcp-memory.md` 接一个 MCP memory server，跑通：

1. 会话 A：告诉 agent "记住这个客户偏好邮件联系"。
2. 新开会话 B：问"这个客户偏好什么联系方式"，看它能不能答。

**如果答不上来**，先检查：memory 工具有没有出现在工具列表里？模型有没有被触发去调用它？必要时在指令里加一句"用户要求记住时，调用记忆写入工具"（官方指南也建议了这句话）。

## 六、常见误解

**"指令写得越详细，模型表现越好。"**
超过临界点后是负收益：占用上下文、稀释注意力、还可能自相矛盾。写"约束"和"格式"，不写"教程"。

**"skill 就是提示词模板。"**
它是有发现规则、有生命周期、有作用域的一等能力。目录常驻、正文按需，这个分离是它省上下文的关键。

**"记忆就是存向量。"**
存什么、何时写、何时删，比用什么索引重要得多。先想清楚策略，再选存储。
