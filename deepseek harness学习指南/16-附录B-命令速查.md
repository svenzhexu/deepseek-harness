# 附录 B · 命令速查

> 全部在仓库根目录执行。Windows 用 PowerShell。

---

## 一、环境

```powershell
node -v                     # 需要 22.19+ 或 24+
corepack enable             # 启用项目 pin 的 pnpm
pnpm -v                     # 期望 11.28.5
pnpm install
pnpm run typecheck          # 首次基线
pnpm run build
```

**只做阅读时**，`pnpm install` 之后就可以停了；`build` 只在要从源码运行时才需要。

---

## 二、运行

```powershell
pnpm dsh web                                  # 源码启动 Web，默认 http://127.0.0.1:3080
pnpm dsh web --no-open                        # 不自动开浏览器
pnpm dsh --profile web --dump-config          # 打印完整插件树
pnpm dsh --profile headless "处理工单 T-1024"   # 一次性执行
pnpm dsh web --patch ./tmp/my-agent.yml       # 叠加自定义配置
pnpm dsh plugin ...                           # 插件管理（安装到 profile）
```

> 桌面客户端跑的是 `app.asar` 里的打包副本。**验证源码改动一律用 `pnpm dsh web`。**

---

## 三、开发

```powershell
pnpm run dev:web            # 构建 + 启动 + 客户端热更新
pnpm run build:artifacts    # 只构建产物
pnpm run build:check        # 类型检查（基于已有产物）
pnpm run lint               # oxlint
pnpm run duplication        # 跨文件克隆检测
```

日常节奏：改代码 → `build:artifacts` → 验证；提交前 `build:check`。

---

## 四、测试

```powershell
pnpm run test               # 单测
pnpm run test:coverage      # CI 覆盖率门（per-file 100%）
pnpm run test:snapshot      # 录制会话回放，无需 API key
pnpm run test:e2e           # 真实 API，无 key 自动跳过
pnpm run test:expected      # 进程级期望
```

**`test:snapshot` 是学习利器**：它用录制好的会话回放整条链路，不需要 key，也不会花钱。

筛选单个用例：

```powershell
pnpm run test:snapshot -- -t "工具名"
```

## 七、环境变量

| 变量 | 用途 |
|---|---|
| `DEEPSEEK_API_KEY` | 真实模型调用 |
| `DEEPSEEK_BASE_URL` | 兼容端点 |
| `DSH_HOME` | Harness 数据目录（profiles、sessions） |
| `DSH_GATE_CONCURRENCY` | 构建门并发度（`1` 顺序执行） |
| `DSH_GATE_FAIL_FAST` | 第一个失败就停 |

`.env` 放在仓库根会被读取（已 gitignore）。**不要提交任何密钥。**

## 八、排障

| 症状 | 先查 |
|---|---|
| 插件没加载 | 它的 `inject` 依赖在不在？`--dump-config` 里有没有？ |
| 全仓库类型报红 | `pnpm install` 跑了吗？VSCode 用 workspace TS 版本了吗？ |
| 改了源码没效果 | 是不是用桌面客户端验证的？要用 `pnpm dsh web` |
| 构建报 TS 版本错 | `node --experimental-strip-types` 有没有被禁？ |
| 端口冲突 | Web 默认 3080；端口属于 Web 服务配置，改 profile 里的对应行，不要指望命令行开关 |
